# 自动规则（Rules）

自动聚类擅长“起名”，不擅长“一致”：同一个客户，周一分到「客户A」，周三可能分成「对账」「客户A2」两条。
规则就是给这类重复活动一条确定性的归口：**命中即归入事项，不依赖模型，不依赖当天数据分布。**

规则在流水线里的顺序（先到先得，后者覆盖前者）：

1. **自动规则**（本文）— 确定性，每次重新处理都会重跑
2. **学到的别名**（你在复核页手动打标时自动学习）
3. **聚类 + 命名**（TF-IDF，可选用本地模型）

人工标签始终最高优先：`process` 会保留你确认过的标签，规则不会覆盖它。

## 条件

一条规则可以有 0–4 个条件，**同时满足**才命中；全部留空视为“无条件”，永远不会命中。

| 字段 | 匹配对象 | 说明 |
| --- | --- | --- |
| `app` | 应用名 | 如 `excel`、`chrome` |
| `title` | 窗口标题 + 网页标题 | 如 `对账` |
| `url_domain` | 网址 + 页面标题 | 如 `example.com` |
| `focused` | 焦点输入框文本 | 仅在采集了焦点文本时有效 |

每个条件的写法：

- `对账` — 包含（不区分大小写，默认）
- `=Excel` — 完全相等
- `re:^2026-\d{2} 对账` — 正则（不区分大小写）

优先级 `priority` 越大越先匹配；同一段只会被第一条命中的规则打标。

## CLI

```bat
wt rules list
wt rules add --name "所有 Excel 对账" --app excel --matter "客户A / 对账" --task "核对账目"
wt rules add --name "发票台" --domain invoice.example.com --matter "客户B / 开票"
wt rules add --name "正则示例" --title "re:^2026-\d{2} 对账" --matter "客户A"
wt rules test --date 2026-11-12        :: 只统计命中，不修改数据
wt rules rm --id 3
```

## 复核页

`⚙ 设置 → 自动规则` 可以图形化增删、启停、测试命中；抽屉里「存为规则」会把你正在看的这一段
（应用名 + 域名或标题）直接填成一条草稿，确认即可。

## 什么时候该用规则，而不是手动打标

| 场景 | 建议 |
| --- | --- |
| 每天都要处理的同一批客户/项目文件 | 规则（标题或域名） |
| 一个网站里多个客户混在一起 | 规则（URL 路径）+ 手动微调 |
| 只出现一次的活动 | 手动打标，别加规则 |
| 规则写得过宽（比如只写 `app=chrome`） | 加 `title` 或 `url_domain` 收窄 |

规则保存在本地 SQLite 的 `rules` 表里，`wt rules list` 的 `hits` 列会显示每条规则累计命中次数，
便于回头清理写错的规则。
